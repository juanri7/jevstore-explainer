The feed that reads your mind while you shop.

JevStore is a prototype store where hovering over products teaches Jev what you want. Upcoming rows are pre-filled before you scroll to them — each card badged with a Jev match score.

How it works — three moves

1 · Signal

Browser watches intent

Hover dwell ≥600ms, scroll-velocity slowdown, clicks, add-to-carts. Debounced, last ~20 events, memory-only. Reset wipes it.

{ sku, type: "dwell", dwellMs: 1240 }

2 · Noul profile

Jev scores interest

POST /api/profile asks Jev: “probability the shopper wants category X?” Top categories render as live probability bars.

q0: { type: "noul", … } → { "sneakers": 0.82 }

3 · Choice rank

Rows fill before you scroll

POST /api/rank ranks ~10 candidates via Jev Choice. Sorted by probability, shown as match-% badges on the injected row.

rank: { type: "choice", criteria: {…} }

Why Jev — not rules

No quiz, no login, no hard filters. The interest profile emerges from the first 3 dwells (cold-start sprint) and updates every ~2.5s. Same UI can run adaptive vs popularity — the metrics strip logs hovers, avg dwell, clicks, carts per mode. That’s the proof.

  • Ghost panel: transparency as a feature — watch the machine read you.
  • Server proxy: browser never holds the key; server/app.py calls Jev via vault CLI or JEV_API_KEY.
  • Catalog: ~600 SKUs from 194 real records + seeded mock variants.
# profile — what does Jev think?
state:
  "Dwelled 1.2s on 'Runner X' (sneakers)
   Clicked 'Gym Duffel' (bags)"
questions:
  q0: is interested in 'sneakers'
  q1: is interested in 'bags'

# rank — what fills the next row?
state: "interests: sneakers 0.82, bags 0.61"
questions:
  rank: { type: choice, criteria: { sku: title… } }
→ [{ sku, p: 0.87 }, …]  # match-% badges
