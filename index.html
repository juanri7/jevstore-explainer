Live intent, not history · demo + explainer

The feed that reads your mind while you shop.

Linger on a pair of sneakers and sneaker-adjacent rows start appearing before you scroll to them — each pick stamped with a match score. No quiz, no login, no search. That is Jev, a fast system-one model, reading in-session intent and ranking the shelves around it.

Why this matters — in plain English

Shoppers

Shelves that keep up with you

Today's recommendations are frozen: same best-sellers for everyone, blind to what you looked at ten seconds ago. Here the feed notices mid-browse and adjusts — the store feels attentive instead of generic.

Speed

Ranked before you arrive

Ranking a row is a judgment call, not an essay. Jev answers in milliseconds, so rows are ready before they scroll into view. No spinner, no stalled feed — a frontier-model round-trip could never keep up with infinite scroll.

Trust

It can only pick real products

Jev ranks a fixed set of actual shelf items — it cannot invent one that doesn't exist. And the ghost panel shows its working live. Flip the toggle OFF and feel the same feed go dead: that gap is the evidence.

How it works — three moves

1 · Signal

Browser watches intent

In plain terms: lingering, slowing down, clicking, and carting are votes. Technically: hover dwell ≥600ms, scroll-velocity slowdown, clicks, add-to-carts → debounced stream, last ~20 events, memory-only. Reset wipes it.

{ sku, type: "dwell", dwellMs: 1240 }

2 · Noul profile

Jev scores interest

In plain terms: Jev turns your votes into odds per category, live. Technically: POST /api/profile asks Noul questions over the last ~8 signals — “probability the shopper wants category X?” — rendered as probability bars.

q0: { type: "noul", … } → { "sneakers": 0.82 }

3 · Choice rank

Rows fill before you scroll

In plain terms: the next row is chosen from real shelf items, never invented. Technically: POST /api/rank runs one Choice question over ~10 candidates; per-option probabilities render as match-% badges.

rank: { type: "choice", criteria: {…} }

Why Jev — not rules

No quiz, no login, no hard filters. A usable interest profile emerges from roughly the first 3 dwells and refreshes every ~2.5s. Same UI runs adaptive vs popularity — the metrics strip logs hovers, avg dwell, clicks, carts per mode. That’s the proof.

  • Ghost panel: transparency as a feature — watch the machine read you.
  • Server proxy: browser never holds the key; server/app.py calls Jev via vault CLI or JEV_API_KEY.
  • Catalog: 578 SKUs from real records (titles, prices, categories, hosted photos) + seeded mock variants.
# profile — what does Jev think?
state:
  "Dwelled 1.2s on 'Runner X' (sneakers)
   Clicked 'Gym Duffel' (bags)"
questions:
  q0: is interested in 'sneakers'
  q1: is interested in 'bags'

# rank — what fills the next row?
state: "interests: sneakers 0.82, bags 0.61"
questions:
  rank: { type: choice, criteria: { sku: title… } }
→ [{ sku, p: 0.87 }, …]  # match-% badges
